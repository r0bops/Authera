Outcome: the confirmed application defects found in this pass were fixed and covered by regression tests. The app is demo-ready and all automated checks pass. It is not yet production-ready because rate limiting, complete passkey enrollment/UI, and a live Yuno sandbox validation remain open.

Fixed findings

Fixed · High · Authorization — cross-user execution and evidence access

Authenticated humans could list global executions/audit events and fetch arbitrary receipts, verification records, evidence exports, AP2 envelopes, or open disputes by execution UUID.

Fix: added database-scoped ownership queries and a central requireExecutionAccess guard. Lists now join through the owning mandate or agent, and direct-ID routes return 404 outside that boundary. A real-PostgreSQL cross-user regression suite covers every affected route.

Fixed · High · Payment integrity — webhook values were not reconciled

A validly signed provider event could settle a reservation even when its amount, currency, provider, or established provider payment ID disagreed with the stored payment.

Fix: webhook settlement now compares all four values with server-owned payment data. Mismatches are retained in the webhook ledger, marked REJECTED, logged without values, and never change payment or reservation state.

Fixed · Medium · Agent identity — key validity and production discovery

Active agent keys were accepted before validFrom or after validUntil. Public discovery was also hard-coded to the seeded demo user, leaving non-demo agents undiscoverable.

Fix: signature verification enforces the persisted validity window, discovery filters expired/revoked keys at the injected clock, and directory/profile lookup now covers database agents instead of one seed identity.

Fixed · Medium · Availability — request bodies were allocated before limits

Human and webhook bodies had no pre-read cap, while agent/webhook checks measured data only after buffering it.

Fix: an application-wide 256 KiB streaming body limit now runs before route parsing, while the stricter 64 KiB signed-agent limit remains in force.

Fixed · Low · Session hardening — configured session secret was unused

Opaque session tokens were stored as plain SHA-256 hashes and the required session secret did not participate in lookup.

Fix: persisted token identifiers now use HMAC-SHA-256 with SESSION_SECRET.

Fixed · Low · Performance and maintenance — monolithic bundle and dead code

The web build emitted a 572 KB single-chunk warning. One unused phase script, one unused direct dependency, unused hooks/components/helpers, unnecessary exports, and stale phase-divider comments remained.

Fix: route modules are lazy-loaded (largest initial chunk about 413 KB, no warning); the unused script, dependency, code, exports, and stale commentary were removed.
